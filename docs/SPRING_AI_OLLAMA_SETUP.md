# Spring AI and Ollama setup
## Architecture
The investigation service now depends on the provider-neutral `InvestigationAi` interface. The default `mock` provider remains deterministic and offline. Set `APP_AI_MODE=ollama` to activate `OllamaInvestigationAi`, which uses Spring AI's Ollama starter and a locally hosted model.
Spring AI 1.1.8 is used because the Spring AI 1.1.x line is compatible with Spring Boot 3.5.x. See the official [Spring AI Ollama reference](https://docs.spring.io/spring-ai/reference/api/chat/ollama-chat.html) and [Spring AI project compatibility notes](https://github.com/spring-projects/spring-ai).
## 1. Install Ollama
Install Ollama for your operating system from https://ollama.com/download. Start Ollama and open a terminal.
Pull the default small model:
```bash
ollama pull llama3.2:3b
```
Confirm it is available:
```bash
ollama list
```
A 3B quantized model is a practical starting point for a machine without a dedicated GPU, but generation can be slow and RAM needs depend on quantization, context length, and other running applications. Close memory-heavy applications if needed.
## 2. Keep Mock mode by default
Without environment changes, the application continues using Mock AI:
```properties
app.ai.mode=mock
```
This mode does not require Ollama to be running and should be used for automated tests.
## 3. Enable Ollama mode
Set environment variables before starting Spring Boot.
Windows PowerShell:
```powershell
$env:APP_AI_MODE="ollama"
$env:OLLAMA_MODEL="llama3.2:3b"
$env:OLLAMA_BASE_URL="http://localhost:11434"
```
Then start the application from the same PowerShell session. In Eclipse, use **Run Configurations → Environment** to add the same three variables and launch the application.
The app property `app.ai.mode` resolves from `APP_AI_MODE`, defaulting to `mock`. Model auto-pull is disabled; pull the model explicitly with `ollama pull` so application startup does not unexpectedly download large files.
## 4. Run an investigation
Use the existing endpoint:
```http
POST /api/investigations
X-User-Id: demo-user
Content-Type: application/json
```
```json
{
  "question": "What is the maximum upload size?",
  "limit": 5
}
```
Upload a relevant TXT or text-based PDF first. A successful response should report `aiMode: "ollama"`. The conclusion should include server-generated source citations based on validated chunk IDs. The response is still generated by an LLM and must be verified against the referenced source excerpts.
## 5. Failure behavior
If Ollama is stopped, the model is missing, or the LLM response is malformed, the investigation is marked `FAILED` and returns a safe generic processing-error conclusion. Detailed provider exceptions are not returned to API callers. Check the local application logs for troubleshooting, but do not log entire document contents or prompts containing sensitive data.
## 6. Evidence safety
- Only evidence already retrieved within the requesting user's ownership scope is sent to the model.
- Excerpts are described as untrusted data, not instructions, to reduce prompt-injection risk.
- The model's cited chunk IDs are checked against the retrieved evidence set.
- A `COMPLETED` answer without a valid cited chunk is downgraded to `INSUFFICIENT_EVIDENCE`.
- This is a practical guardrail, not a guarantee that a model cannot hallucinate. Verify source excerpts and effective dates.
## 7. Automated tests
Keep `app.ai.mode=mock` for `mvn clean test`. Tests do not need Ollama or a GPU. Do not enable Ollama in the test profile unless explicitly writing an Ollama integration test and the local model service is available.
